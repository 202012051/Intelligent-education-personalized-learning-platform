# Feature Specification: 智能教育个性化学习平台

**Feature Branch**: `001-iep-learning-platform`

**Created**: 2026-06-01

**Status**: Draft

**Input**: User description from 02-specify.md — 智能教育个性化学习平台 MVP，两周冲刺交付，验证认知诊断、贪心推荐、学习风格识别三个核心假设。

## Clarifications

### Session 2026-06-01

- Q: 测评题目来源？ → A: 由罗家豪基于示例课程（Python 程序设计基础）手工编制，每个核心知识点 2-3 题共 10 题，已内置到数据库初始化脚本。MVP 仅覆盖 1 门课程。
- Q: 学习风格问卷位置？ → A: 学生登录后可在个人中心随时完成，非强制流程，MVP 阶段不自动弹出。
- Q: 测评是否必须？ → A: 可浏览课程和知识图谱，但生成个性化学习路径必须完成测评。未测评时推荐接口返回"请先完成课程测评"。
- Q: 教师如何注册？ → A: 前端注册默认角色为"学生"，教师账号由管理员通过 SQL 直接插入数据库（MVP 限制）。初始化脚本需预置至少 1 个教师账号。
- Q: 学习路径何时刷新？ → A: 自动触发（每次学习行为记录后）+ 手动获取（调用 `/api/courses/{id}/learning-path`）。推荐接口需支持幂等调用，前端每次进入仪表盘重新拉取。
- Q: 知识图谱节点颜色策略？ → A: 三色：🟢已掌握(mastery≥0.70)、🟡学习中(0<mastery<0.70)、⚪未学习(mastery=0或未测评)。
- Q: 前端状态管理方案？ → A: 使用 Zustand（轻量级状态管理库）。
- Q: 数据备份策略？ → A: MVP 不需要自动化备份，演示前手动 `mysqldump` 导出。
- Q: 错误处理粒度？ → A: 统一 `ApiResult {code, message, data, timestamp}` 格式。参数校验返回字段级错误，业务异常返回中文提示，系统异常返回"服务器内部错误"。
- Q: 是否支持头像上传？ → A: MVP 仅支持设置头像 URL 字符串，不上传真实文件。前端用输入框而非文件选择器。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用户注册与认知诊断 (Priority: P1) 🎯 MVP

新用户（学生）注册账号后，完成一套 10 题的初始测评问卷（基于 Python 程序设计基础课程，每个核心知识点 2-3 题），系统基于规则引擎判定各知识点的掌握状态（正确率 >70% 视为已掌握），生成初始知识状态并引导进入学习仪表盘。测评非强制——学生可跳过测评直接浏览课程和知识图谱，但生成个性化学习路径必须完成测评。

**Why this priority**: 认知诊断是平台个性化能力的起点——没有诊断就无法生成个性化路径，所有后续推荐和洞察都依赖于知识状态的建立。

**Independent Test**: 可独立完成"注册 → 登录 → 答题 → 查看诊断结果 → 跳转仪表盘"全流程验证。

**Acceptance Scenarios**:

1. **Given** 新用户未注册，**When** 用户使用邮箱和密码完成注册并登录（前端注册默认角色为"学生"），**Then** 系统引导至测评问卷页面，或学生可选择"稍后测评"直接进入课程浏览。
2. **Given** 用户在测评中回答了全部 10 题，**When** 提交答卷，**Then** 系统按知识点维度计算正确率，标记 >70% 的知识点为"已掌握"，并持久化存储知识状态。
3. **Given** 用户中途退出测评，**When** 再次登录，**Then** 系统提示"测评未完成"并允许从上次中断处继续答题。
4. **Given** 测评完成，**When** 诊断结果生成完毕，**Then** 系统自动跳转至学习仪表盘，展示当前知识掌握概览。

---

### User Story 2 - 个性化学习路径与进度跟踪 (Priority: P1) 🎯 MVP

学生查看系统基于其知识状态生成的个性化学习路径，路径按贪心策略排序（薄弱知识点优先，同时满足先修关系约束）。学生按路径学习知识点，系统自动记录学习行为（答题、浏览、视频进度）并实时更新知识状态，路径随之动态调整。

**Why this priority**: 学习路径是个性化的核心交付物，直接验证"千人千面"假设。没有学习路径的 MVP 无法体现平台核心价值。

**Independent Test**: 完成诊断后，验证路径生成、学习记录、状态更新的闭环。

**Acceptance Scenarios**:

1. **Given** 学生已完成认知诊断且存在未掌握的知识点，**When** 进入"学习路径"页面，**Then** 系统按薄弱优先+先修关系排序展示推荐学习路径，每项附带推荐理由（如"该知识点掌握度仅 30%"）。前端每次进入仪表盘时重新拉取学习路径。
2. **Given** 学生未完成测评，**When** 调用学习路径推荐接口，**Then** 系统返回提示"请先完成课程测评"，不生成路径内容。
3. **Given** 知识图谱中知识点 B 的先修要求是知识点 A，且学生两者均未掌握，**When** 生成学习路径，**Then** 知识点 A 排在 B 之前。
4. **Given** 学生在学习某知识点时完成答题或浏览页面，**When** 行为发生，**Then** 系统自动记录学习行为（类型、时间、关联知识点），触发知识状态重新计算，前端可在下次进入仪表盘时获取更新后的学习路径。
5. **Given** 学生通过学习将某知识点掌握度提升至 >70%，**When** 知识状态更新，**Then** 学习路径自动将该知识点移出"待学习"列表，后续路径重新排序。
6. **Given** 所有知识点均已掌握，**When** 查看学习路径，**Then** 系统显示"恭喜，你已掌握所有知识点！"并展示总体学习统计。

---

### User Story 3 - 知识图谱可视化与学习仪表盘 (Priority: P1) 🎯 MVP

学生通过交互式知识图谱（力导向图）直观查看课程知识点之间的先修/包含/相关关系，节点颜色标注掌握状态：🟢已掌握（mastery≥0.70）、🟡学习中（0<mastery<0.70）、⚪未学习（mastery=0或未测评）。学习仪表盘集中展示进度概览、推荐路径摘要、知识热力图和最近学习记录。

**Why this priority**: 知识图谱可视化和仪表盘是平台最直观的差异化能力展示，也是 MVP 演示时的核心体验亮点。

**Independent Test**: 进入仪表盘和知识图谱页面，验证节点渲染、颜色标注、交互（拖拽/缩放/点按详情），以及仪表盘各模块数据一致性。

**Acceptance Scenarios**:

1. **Given** 课程已配置知识点及关系，**When** 学生进入知识图谱页面，**Then** 系统以力导向图渲染知识点节点，节点间连线表示先修/包含/相关关系，节点颜色根据学生掌握状态标注。
2. **Given** 知识图谱已渲染，**When** 学生拖拽、缩放图谱或点击某节点，**Then** 图谱平滑响应拖拽和缩放，点击节点弹出详情（知识点名称、描述、掌握度、关联课程）。
3. **Given** 学生已完成部分学习，**When** 进入学习仪表盘，**Then** 系统展示：总体学习进度百分比、当前推荐的下一个学习知识点、最近 7 天学习记录列表、本周学习时长统计。
4. **Given** 学生知识状态发生变化（如完成某知识点的学习），**When** 刷新仪表盘或知识图谱，**Then** 对应节点的掌握状态颜色和仪表盘进度数据同步更新。

### User Story 4 - 学习风格识别与学习报告 (Priority: P2)

学生可在个人中心随时完成 Felder-Silverman 四维度学习风格问卷（8 题，非强制流程，不自动弹出），系统识别其学习风格类型并以雷达图展示结果。学习报告汇总学生的知识点掌握度（柱状图）、薄弱点分析、学习进度趋势和改进建议。

**Why this priority**: 学习风格和学习报告是增值功能，依赖基础学习数据积累。在核心闭环（诊断→推荐→学习）稳定后可迭代。

**Independent Test**: 可独立完成问卷 → 查看风格结果 → 生成学习报告的完整流程。

**Acceptance Scenarios**:

1. **Given** 学生已登录，**When** 进入个人中心并打开学习风格问卷入口完成 8 道 FS 风格问卷，**Then** 系统判定四个维度的风格倾向（活跃/沉思、感悟/直觉、视觉/言语、序列/综合），并以雷达图可视化展示。
2. **Given** 学生已有学习记录，**When** 生成学习报告，**Then** 系统展示：各知识点掌握度柱状图、得分最低的 3 个薄弱知识点、近 7 天/30 天学习进度趋势图、基于薄弱点的个性化改进建议。
3. **Given** 学生无任何学习记录（仅完成诊断），**When** 生成学习报告，**Then** 系统展示初始知识状态并提示"完成更多学习后报告将更加完善"。
4. **Given** 学习风格结果已生成，**When** 学生后续学习行为数据积累，**Then** 系统保留风格结果作为参考，不强制重新测试。

---

### User Story 5 - 教师课程管理与学情分析 (Priority: P2)

教师创建课程并定义课程下的知识点体系，设置知识点之间的先修关系、包含关系和关联关系。教师查看班级学情概览，包括整体学习进度、平均掌握度、薄弱知识点 Top 5，并能下钻查看单个学生的学习详情。

**Note**: MVP 阶段教师账号由管理员通过 SQL 直接插入数据库（前端注册默认角色为"学生"），初始化脚本需预置至少 1 个教师账号。

**Why this priority**: 教师端功能为内容供给侧提供支持，依赖学生端核心功能的数据产出，可在 MVP 后期完成并用于演示教师视角。

**Independent Test**: 教师独立完成"创建课程 → 添加知识点 → 定义关系 → 查看班级学情"全流程。

**Acceptance Scenarios**:

1. **Given** 教师已登录，**When** 创建新课程并添加知识点（名称、描述、难度等级），**Then** 课程和知识点成功保存，可在课程列表中查看。
2. **Given** 课程已包含多个知识点，**When** 教师定义知识点之间的关系（先修/包含/相关），**Then** 关系被存储并反映在知识图谱渲染中。
3. **Given** 班级中有学生已开始学习，**When** 教师进入"班级学情"页面，**Then** 系统展示：班级整体学习进度、各知识点平均掌握度、班级薄弱知识点 Top 5（按平均掌握度升序）。
4. **Given** 教师查看薄弱知识点列表，**When** 点击某薄弱知识点，**Then** 系统下钻展示该知识点对应的学生详情列表（每个学生的掌握度和最近学习时间）。
5. **Given** 教师查看学情，**When** 选择某学生查看详情，**Then** 系统展示该学生的知识状态、学习进度、最近活动记录。

### Edge Cases

- 测评问卷中所有题目均回答正确（正确率 100%）时，系统如何初始化学习路径？
- 知识图谱中知识点 A 先修 B、B 先修 C、C 又先修 A，存在循环依赖时，学习路径生成器如何处理？
- 学生在测评中途关闭浏览器或网络中断，答题进度如何保存和恢复？
- 学生同时属于多个课程/班级时，知识状态和学习路径如何合并展示？
- 教师删除课程或知识点后，已有学生的学习记录和知识状态如何处理？
- 并发场景：教师修改知识点关系的同时，学生正在查看基于旧关系生成的学习路径？
- 学习报告生成时学生无任何学习记录（仅完成诊断），报告应展示什么？
- 同一学生反复完成同一知识点的学习内容，进度统计是否去重？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持邮箱注册和登录，密码使用 BCrypt 加密存储，登录后签发 JWT Token。
- **FR-002**: 系统 MUST 区分学生和教师两种角色，提供不同的功能界面和权限集。
- **FR-003**: 系统 MUST 提供 10 题的初始测评问卷（基于 Python 程序设计基础课程，每个核心知识点 2-3 题），题目已内置在数据库初始化脚本中。完成后生成知识状态（每个知识点的掌握度）。MVP 仅覆盖 1 门课程。
- **FR-004**: 系统 MUST 使用规则引擎判定认知诊断结果，掌握度分三个等级：已掌握（mastery ≥ 0.70）、学习中（0 < mastery < 0.70）、未学习（mastery = 0 或未测评）。
- **FR-005**: 系统 MUST 基于贪心策略生成个性化学习路径：优先推荐掌握度最低的知识点，同时满足先修关系约束。未完成测评时推荐接口 MUST 返回"请先完成课程测评"而不生成路径。推荐接口 MUST 支持幂等调用。
- **FR-006**: 系统 MUST 为学习路径的每一项提供推荐理由（如"该知识点掌握度仅 X%"或"先修要求未满足"）。
- **FR-007**: 系统 MUST 自动记录学生的学习行为，包括：答题（对/错/时间）、页面浏览、视频观看进度、学习时长。
- **FR-008**: 系统 MUST 在学习行为发生后自动重新计算知识状态，前端可在每次进入仪表盘时重新拉取学习路径（推荐接口幂等）。学习路径也支持手动调用 `/api/courses/{id}/learning-path` 获取。
- **FR-009**: 系统 MUST 以力导向图（Force-Directed Graph）的形式可视化知识图谱，支持节点拖拽、缩放、点击查看详情。
- **FR-010**: 系统 MUST 使用三色标注知识图谱节点的掌握状态：🟢 已掌握（mastery ≥ 0.70）、🟡 学习中（0 < mastery < 0.70）、⚪ 未学习（mastery = 0 或未测评）。
- **FR-011**: 系统 MUST 提供学习仪表盘，展示：总进度百分比、推荐学习路径摘要、知识热力图、最近学习记录、学习时长统计。
- **FR-012**: 系统 MUST 提供 Felder-Silverman 四维度学习风格问卷（8 题），完成后以雷达图展示风格结果。
- **FR-013**: 系统 MUST 生成学习报告，包含：知识点掌握度柱状图、薄弱知识点分析（得分最低 3 个）、进度趋势图、个性化改进建议。
- **FR-014**: 系统 MUST 支持教师创建课程、添加/编辑/删除知识点，并定义知识点之间的先修、包含、相关三种关系。
- **FR-015**: 系统 MUST 提供教师端班级学情概览，展示：整体学习进度、平均掌握度、薄弱知识点 Top 5、学生排行榜。
- **FR-016**: 系统 MUST 支持教师下钻查看单个学生的详细信息（知识状态、进度、活动记录）。
- **FR-017**: 系统 MUST 确保知识图谱中不存在循环依赖（如 A 先修 B、B 先修 A），在教师定义关系时进行校验。
- **FR-018**: 系统 MUST 支持测评中途断点续答，答题进度实时保存。

### Key Entities

- **用户 (User)**: 平台使用者，包含邮箱、加密密码、角色（学生/教师，前端注册默认为"学生"）、昵称、头像 URL（MVP 仅支持 URL 字符串，不上传真实文件）等基本信息。
- **课程 (Course)**: 包含课程名称、描述、创建教师，关联多个知识点。
- **知识点 (KnowledgePoint)**: 课程的知识单元，包含名称、描述、难度等级，通过关系与其他知识点关联。
- **知识点关系 (KnowledgeRelation)**: 两个知识点之间的关联，类型为先修(prerequisite)、包含(contains)或相关(related)。
- **测评题目 (Question)**: 诊断问卷题目，关联到一个或多个知识点，包含题目内容、选项、正确答案。
- **知识状态 (KnowledgeState)**: 学生在某知识点上的掌握度（0-100%），由测评或后续学习行为计算得出。
- **学习路径项 (LearningPathItem)**: 推荐的学习项，包含知识点、排序权重、推荐理由、生成时间。
- **学习记录 (LearningRecord)**: 学习行为记录，包含类型（答题/浏览/视频）、关联知识点、耗时、时间戳。
- **学习风格结果 (LearningStyleResult)**: Felder-Silverman 四个维度的得分（活跃/沉思、感悟/直觉、视觉/言语、序列/综合），以雷达图数据存储。
- **学习报告 (LearningReport)**: 包含生成时间、知识点掌握度列表、薄弱点 Top 3、进度趋势、改进建议文本。
- **班级学情 (ClassAnalytics)**: 教师视角的聚合数据，包含整体进度、平均掌握度、薄弱点排名、学生排行榜。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新用户从注册到完成首次认知诊断并看到结果，总耗时不超过 5 分钟。
- **SC-002**: 个性化学习路径在知识状态变更后 2 秒内完成重新排序并展示。
- **SC-003**: 知识图谱力导向图（含 50 个节点）在页面首屏加载后 3 秒内完成渲染并可交互。
- **SC-004**: 学习行为记录后，知识状态和仪表盘数据在 1 秒内完成更新并反映到前端。
- **SC-005**: 系统支持 100 名学生同时在线学习，无性能降级（API 非推荐类响应 ≤500ms P99，推荐类 ≤2s P99）。
- **SC-006**: 核心模块单元测试覆盖率 ≥70%，端到端核心流程无阻断性 Bug。
- **SC-007**: 90% 的学生能在首次测评中完整提交问卷（无需中途放弃或求助）。
- **SC-008**: 教师可在 10 分钟内完成一个新课程的知识点录入和关系定义（假设 20 个知识点）。

## Assumptions

- 项目为两周冲刺 MVP，架构采用模块化单体，不拆微服务。
- 知识图谱采用 MySQL + JSON 字段存储（不使用 Neo4j），前端使用 ECharts 力导向图渲染。
- 贪心推荐算法为规则引擎驱动，不引入机器学习模型。
- 管理员功能 MVP 阶段不开发界面，直接操作数据库。
- OAuth2.0/SSO 认证不在 MVP 范围内，仅实现邮箱+密码注册登录。
- 学生与教师的基础用户数据由系统统一管理，不依赖外部用户系统。
- 测评题目由罗家豪（算法工程师）基于 Python 程序设计基础课程手工编制（每个核心知识点 2-3 题，共 10 题），已内置到数据库初始化脚本。本期不包含题目编辑器。
- 系统适配 Chrome 80+/Firefox 80+/Edge 80+ 桌面浏览器，不涉及移动端。
- 数据脱敏遵循《个人信息保护法》，学习行为数据不关联用户真实身份信息。
- 前端状态管理使用 Zustand（轻量级库，API 简洁，适合中小型项目）。
- MVP 阶段不需要自动化数据备份，演示前手动 `mysqldump` 导出即可。
- API 错误响应统一为 `ApiResult {code, message, data, timestamp}` 格式：参数校验错误返回字段级错误列表，业务异常返回中文提示，系统异常返回"服务器内部错误"（不暴露堆栈）。
- 头像功能 MVP 仅支持设置 URL 字符串输入，不上传真实文件（前端输入框，不接入文件存储）。
